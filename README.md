# KULLER INDEX

Настольное приложение для Windows: поиск, отбор и обработка рабочих документов.
Картотека хранит записи о файлах (путь, дата, размер, теги, контрагент, текст для поиска),
а оригиналы остаются там, где лежат.

## Запуск из исходников

Нужен [Node.js 18+](https://nodejs.org) (ставится один раз, LTS-версия).

```powershell
cd kuller-index
npm install
npm start
```

Первый `npm install` скачивает Electron, это несколько минут.

## Сборка .exe

```powershell
npm run dist
```

Команда делает три вещи подряд: чистит `dist` от прошлой сборки, поднимает последнюю цифру версии
и собирает. Номер версии в шапке приложения, в имени установщика и в окне «Папки» всегда от текущей
сборки, вручную его править не нужно.

В папке `dist` появится `KULLER INDEX Setup <версия>.exe` — установщик с ярлыком на рабочем столе.
На первом экране он спрашивает папку установки, так что программу можно поставить на любой диск.

Быстрая проверка без установщика: `npm run pack` — готовая папка в `dist/win-unpacked`.

Собирать нужно на Windows: упаковщик использует системные инструменты Windows.

## Поиск по тексту внутри документов

Простой текст, Markdown и CSV читаются всегда. Для PDF и Word нужны два необязательных пакета,
они ставятся вместе с остальными при `npm install`:

- `pdf-parse` — текст из PDF;
- `mammoth` — текст из .docx.

Если пакеты не установились, приложение работает, но в поиске по содержимому эти форматы
участвовать не будут — об этом честно написано в окне «Папки». Сканы требуют распознавания,
его пока нет.

## Как добавлять документы

Три равноправных способа, все принимают и файлы, и папки:

- **«Добавить папку»** в верхней панели — можно выбрать сразу несколько;
- **«Добавить файлы»** — отдельные документы, сразу с тегами;
- **перетаскивание** из Проводника — файлы и папки вперемешку.

Папка становится наблюдаемой: приложение просматривает её целиком, включая вложенные
(до 12 уровней), и при каждом «Обновить» ищет в ней новое.

### Теги достаются сами

По умолчанию документ получает теги по именам папок, в которых лежит — всех уровней от
добавленной папки и ниже. Файл из `Договоры\2024\Ромашка` получит теги `Договоры`, `2024`
и `Ромашка`.

Имя папки сверяется с уже существующими тегами без учёта регистра: папка `РОМАШКА` даст
существующий тег `Ромашка`, а не второй его вариант. Заведомо служебные имена — `Новая папка`,
`tmp`, `Документы`, `Загрузки` — тегами не становятся, если вы сами не завели тег с таким именем.

При добавлении папки окно показывает дерево её подпапок: сколько в каждой документов и какие
теги они получат. Теги любой подпапки можно поправить, а кнопка **«Перенести по умолчанию»**
принимает всё как есть.

Правило живёт вместе с папкой: документы, появившиеся в ней позже, получат те же теги при
следующем «Обновить». Теги уже заведённых документов правило не переписывает — они принадлежат
вам. У вложенной папки правило точнее родительского и побеждает. Кнопка «Убрать» в окне «Папки»
снимает наблюдение — записи в картотеке и файлы на диске остаются на месте.

Повторное сканирование перечитывает только изменившиеся файлы: у остальных сверяются дата и
размер, и они пропускаются. Исчезнувшие файлы помечаются, но их записи и теги сохраняются.
Долгий просмотр можно остановить кнопкой «Остановить» — уже найденное останется в картотеке.

## Отмена действий

Стрелки слева от «Обновить» отменяют и возвращают последние 20 действий, то же делают
`Ctrl+Z` и `Ctrl+Y`. Подсказка у стрелки называет действие: «Отменить: теги у 12 документов».

Изменение тегов, контрагента, удаление записей и добавление документов отменяются мгновенно и
без последствий — они не трогают диск. Переименование и перемещение отменяются с проверкой:
файл должен быть на месте, а имя в исходной папке свободно. Если за это время что-то
изменилось, отчёт честно покажет, что вернулось, а что нет.

Удаление в Корзину отменить нельзя: возврат оттуда программе недоступен. Стрелка на таком шаге
неактивна и говорит об этом, вместо кнопки, которая ничего не делает. Восстанавливайте такие
файлы из самой Корзины Windows.

История живёт, пока открыто приложение.

## Горячие клавиши

Полный список — в настройках, под шестерёнкой. Коротко: стрелки ходят по списку, `Пробел`
отмечает, `Shift+стрелки` расширяют выделение, `Enter` открывает файл, `Ctrl+Enter` —
карточку, `Delete` удаляет выделенное, `Ctrl+A` выделяет всё, `Ctrl+F` переводит в поиск,
`Esc` снимает выделение или закрывает панель.

В полях ввода и при открытой боковой панели список клавиши не перехватывает.

## Темы

Две: тёмная и светлая, кнопки с солнцем и полумесяцем в шапке. При первом запуске тема берётся
из настроек Windows один раз, дальше действует ваш выбор. Все цвета заданы переменными
в `styles.css`, палитру можно поменять в одном месте.

## Как устроено

```
src/main/main.js      окна, заставка, маршрутизация запросов интерфейса
src/main/store.js     настройки, каталог и текстовый индекс в JSON (папка данных пользователя)
src/main/catalog.js   сканирование папок, записи документов, индекс текста, теги, поиск
src/main/ops.js       печать, Корзина, перемещение, ZIP, письмо
src/main/history.js   отмена и возврат действий
src/main/preload.js   безопасный мост между интерфейсом и системой
src/renderer/         интерфейс: splash.html, index.html, app.js, styles.css
tests/run.js          проверки каталога и хранилища без Electron (npm test)
```

Данные лежат в `%APPDATA%\kuller-index`: `catalog.json` — записи документов,
`index.json` — текст для поиска, `settings.json` — настройки, папки и их правила тегов. Точный путь показан в окне «Папки».
Текст хранится отдельно от записей, поэтому смена тега переписывает килобайты, а не мегабайты,
и в интерфейс тексты не выгружаются — поиск внутри документов выполняется в главном процессе.

Перед каждой записью предыдущая версия файла сохраняется рядом как `.bak`. Если основной файл
окажется повреждён, он не затирается: приложение отводит его в сторону (`.corrupt-<дата>`),
читает резервную копию и сообщает об этом в окне «Папки».

## Что делают операции

| Операция | Что происходит на самом деле |
| --- | --- |
| Печать | Файлы печатаются строго по очереди одним заданием PowerShell: каждый открывается своей программой (`Start-Process -Verb Print`) с паузой между копиями. В отчёте написано «передан в очередь» — подтвердить сам факт печати Windows не даёт |
| Отправить по почте | Письмо создаётся в Outlook с уже прикреплёнными файлами и открывается для проверки; без Outlook открывается почтовый клиент по умолчанию, вложения показываются в проводнике |
| Создать ZIP | Файлы пишутся в архив потоком средствами .NET, временная копия набора не делается; оригиналы не изменяются, совпадающие имена нумеруются. Если ни один файл не попал в архив, архив удаляется, а не выдаётся за готовый |
| Переместить | Настоящее перемещение оригинала, при переходе между дисками — копирование со сверкой размера и только затем удаление исходного; существующие файлы не перезаписываются |
| Изменить теги | Меняются только метаданные картотеки, файлы не трогаются |
| Убрать из картотеки | Удаляется запись, файл остаётся на диске |
| Удалить с компьютера | Файл отправляется в Корзину Windows, безвозвратного удаления нет |

Каждая массовая операция заканчивается отчётом: выполнено, пропущено, с ошибкой — с причиной по
каждому файлу. Частичный сбой не выдаётся за успех.

## Проверки

```powershell
npm test
```

Прогон сценариев каталога и хранилища без Electron: сканирование вложенных папок с кириллицей,
повторное сканирование, новые и изменившиеся файлы, исчезнувшие файлы, пустые и недоступные папки,
дубликаты, удаление источника, повреждённый каталог и переход со старой схемы данных.
Печать, Корзина, ZIP и письмо опираются на Windows и проверяются вручную.

## Чего пока нет

Синхронизации между компьютерами, общей работы нескольких сотрудников, собственного хранилища
документов, паролей на архивы, отправки через SMTP без почтового клиента, распознавания сканов.
